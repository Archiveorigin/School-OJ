# 考试与团队比赛工作流

考试和团队比赛复用组题、整场审核、排行和归档组件；课程／班级与团队的权限、名单和提交上下文分别校验。权限能力见 [权限方案](authorization.md)，数据文件格式见 [题目包规范](problem-package.md)。

## 1. 创建、编辑与整场送审

创建草稿 → 设置时间、赛制、评阅方式和参与范围 → 组题并配置测试点／附件 → 预览 → 提交整场审核 → 审核通过后按时间开放。退回后修改并重新提交；待审核时不能继续改题，可撤回回到草稿。考试创建向导保存的是草稿，不等于立即公开发布。

组题工作区“本场题目”保持原有列表和编辑器结构。左侧三个操作从上到下排列：新增题目、导入 Markdown 单题、添加现有题目。添加现有题目通过弹窗多选，支持搜索、分页、公共题库与当前团队私有题单；跨页选择保留，已在场内的题目禁选，一次确认作为一个原子变更提交。比赛即使由系统管理员组织，也不能导入其他团队的私有题目。

独立新增的题目不直接进入公共题库，保存为场次专用不可变快照。公共题库更新不自动替换任何场次绑定版本；仅在草稿或退回状态下明确采用最新版本。旧提交始终绑定原快照。

| 标记 | 用途 | 何时变化 |
| --- | --- | --- |
| `review_revision` | 服务端防覆盖的内部并发标记 | 成功修改场次材料时变化；界面不展示为版本号 |
| `submission_version` | 实际送审轮次 | 提交审核成功才增加；普通草稿保存、解析预览和 GET 刷新不增加 |
| `problem_version_id` | 不可变题目内容快照 | 保存题目内容生成，用于复现题面、测试点和历史判题，与送审次数无关 |

说明编辑保留未保存的输入，后台详情刷新和管理页刷新不会清空文本。如果服务端内容与本地编辑同时变化，保存返回 409 提示冲突，保留本地输入供处理。关闭对话框或离开路由时提示未保存修改；保存成功才更新基线。文本框随内容撑开，仍可手动向下调整。页面草稿显示“尚未提交审核”或真实审核次数，不展示内部标记。

## 2. 状态与访问


| 阶段 | 出题管理人员 | 原访问范围内的参与者 | 提交新代码 |
| --- | --- | --- | --- |
| 草稿、待审核、退回 | 管理本场；仅草稿和退回可编辑，待审核可撤回 | 列表不可见，直接访问也拒绝 | 不可 |
| 未开始 | 查看审核后的完整内容；开始前可撤回重新审核 | 只开放说明；题目、附件、提交记录、排名入口隐藏 | 不可 |
| 进行中 | 查看本场 | 校内考试须确认进入且未提前交卷；团队比赛须在冻结名单和当前团队范围内 | 按原参赛权限开放 |
| 已截止 | 检查成绩，完成必要的人工评分或已有提交评测 | 题目、附件、本人提交与原规则允许的排名仍可读；不可修改测试内容 | 所有人均不可 |
| 已完结 | 历史审核只读；评分、重判和状态变更锁定 | 原列表“已归档”按钮不可进入，从菜单“比赛”检索和查看 | 不可 |

- 只有具备整场审核能力的管理员能确认完结，且必须已截止、无排队/运行中的提交、无待人工评分、无系统错误。
- 完结为最终状态，撤销完结接口被拒绝。旧的考试、比赛详情接口返回 `410 / EVENT_COMPLETED`；浏览器旧书签转到仍需鉴权的归档。
- 到时间只变为已截止，不会自动归档；未审核、撤回或逻辑删除的场次不会自动进入归档。
- 归档沿用原班级、课程和团队可见范围，OI 排名和原先关闭的排名保持原规则。
- 已截止校内考试允许原范围内人员读题和下载图片，无需重新进入考试；提前交卷者在考试仍进行时保持原限制。
- 本场附件按钮与组题、设置同排，按权限从左向右显示；附件弹窗在草稿阶段可管理，其他阶段只读。

## 单题导入

只接收 UTF-8 的 `.md` / `.markdown` 文件，最大 200000 字节，也支持粘贴文本。每次必须恰有一个一级标题。先解析预览，再进入编辑器校对并添加测试点；保存后随整场送审。预览和草稿修改不增加送审版本，实际提交审核才增加一次。

````markdown
# 题目标题

## 题目描述
正文和 $a+b$ 等公式。

## 输入格式
输入说明。

## 输出格式
输出说明。

## 样例 1 · 输入
```text
1
```

## 样例 1 · 输出
```text
2
```
````

样例输入和输出各自使用代码块；输出标题为 `## 样例 1 · 输出`。兼容“输入输出样例 #1 / 输入 #1 / 输出 #1”等常见格式。“说明”“说明/提示”可选，空白不展示。多个一级标题会提示拆为单题，避免把整卷误合并成一题。

图片可写为 `![说明](https://example.com/image.png)`。指向 PNG、JPEG、GIF、WebP 的 Markdown 链接、独立 HTTPS 图片网址也会显示图片；代码块中的文本保持不变。浏览器直接加载原图，不向服务器抓图、不上传本地配图。原站不可用或禁止外链时，页面显示失败提示。图片懒加载并禁止发送 Referer，CSP 仅扩展 HTTPS 图片来源，其余脚本和网络限制保持。

当前不提供 PDF 导入、图片匹配上传或服务器抓取外链图片。已存储的受保护题包图片仍通过原鉴权接口读取。


## 3. 测试点、附件与资源

规范题面包括描述、输入、输出、样例与可选提示。样例允许无输入或无输出，保留空格与换行；样例数 1–20。API 和 Worker 题包都限制最多 200 组测试点。

测试点选取最多 400 个 `.in/.out` 文件、总计 128 MiB；按文件名配对。小文件整体上传，超过 1 MiB 的文件使用 1 MiB 分片，客户端最多三个并发请求；预览最多 64 KiB，不把大文件全文塞进编辑器。临时上传按一小时过期回收，权限及内容在最终保存时再次校验。更新时按名字合并测试点，未选择替换的旧测试点保留。

本场附件最多 20 个，单个 32 MiB、合计 96 MiB。附件按钮与组题、设置同排；草稿及退回阶段可维护，其他阶段只读。下载重新验证场次和成员权限，已保存题包图片使用受保护的版本资源接口。

## 4. 草稿奖项设置与人数换算

比赛创建和草稿设置复用金、银、铜三个输入项，单位可切换“比例（%）／人数（人）”。换算基数来自本场排名名单，不再手工填写预计人数。默认团队全体成员；可逐人选择计入／不计入，也可导入 UTF-8 TXT／CSV 用户名名单。精确匹配团队内用户名，重复项去重；未知或同名用户名必须先修正或通过成员邮箱手动确认，不能静默导入。人数模式至少需要一名有效排名人员。人数只作为比例的输入方式，不保存固定获奖配额；切换单位不改比例，不触发额外保存或审核版本。

数据库与 API 保存六位小数百分比，三项均在 0–100 之间且合计不超过 100。人数输入按 `floor(人数 × 100 × 10^6 / 基数) / 10^6` 转为百分比，避免 1/6 四舍五入为 16.666667% 后向上取整变成两个名额。

名单仅影响排名、导出和奖项人数换算，不限制原本有资格的团队成员参加或提交。`ranking_user_ids=null` 表示全体，`[]` 表示不计任何人排名；通过用户 ID 持久化，用户名改变不会丢失身份。名单随整场审核锁定，开赛前撤回后可重新选择；通过审核时再次校验成员有效性。未入选人员的提交仍须正常评测，最终榜单仍等待全场提交完成。

人数模式下修改名单保留已输入的获奖人数，并重新换算比例；名单缩小导致获奖总人数超出基数时阻止保存，要求明确调整。比例模式下修改名单保留比例。移除“奖项占比合计”展示，但前后端继续校验比例合计不能超过 100%；全部设为 0 表示不评奖。

最终奖项按实际榜单人数计算累计边界：金奖 `ceil(N×金%)`、金银合计 `ceil(N×(金%+银%))`、全部奖项 `ceil(N×总比例)`，各级人数由相邻边界相减；实现扣除极小浮点误差并保证结果非负。例：基数 6、金 1／银 0／铜 1，保存 16.666666／0／16.666666，实际人数仍为 6 时得到 1／0／1。实际人数改变或边界同名次时，实际获奖人数可能与输入人数不同；并列保持同奖，不通过截断姓名强行凑配额。

人数基数是编辑辅助值。重新打开时需重新指定，避免把上一次预计人数误认为实际报名或有效参赛人数。迁移 037 的小数存储及回退限制见 [部署流程](deployment.md)。

## 5. 计分、排行榜与最终结果

| 赛制 | 计分与排序 |
| --- | --- |
| ACM | 解题数降序、罚时升序、最后首次通过时间升序；首次通过用时加此前有效错误提交每次 20 分钟，CE 不计罚时 |
| OI | 每题最后一次提交计分；赛中参与者仅见“已记录”，参与者无排行榜入口，管理端按原权限查看 |
| IOI | 每题最高分；总分、满分题数、最后有效得分时间形成稳定排序 |

提交时间窗为 `[开始, 截止)`，截止前提交、截止后评测完成的结果仍计入。并列名次采用 1、1、3；IOI／ACM 封榜与 OI 投影由服务端执行，不能依靠按钮隐藏。

排行榜单独提供 Name 姓名列。金银铜色仅覆盖排名与姓名两格，题目格继续按评测状态着色。过滤不重算全体排名和奖项。页面只展示实时表现，不提供“公布排名”模式选择；通过手动刷新或重新进入页面更新，不提供自动刷新开关及定时刷新榜单。说明页的生命周期检查与提交状态 SSE 不受影响。

`final_ready` 由同一 PostgreSQL 可重复读快照中的截止状态和提交结果共同判断：已截止／已完结，且没有排队、运行、待人工评分或系统错误，才显示最终排名。截止但尚未完成评测时仍是实时结果。管理员确认完结是另一个锁定归档动作，不是计算最终排名的前提；完结后禁止评分和重判。

## 6. 管理审核与导出

有管理权限的用户可查看完整后台榜单，不受参赛者封榜或当前页面筛选影响。导出 Excel、HTML 打印榜单读取完整服务端数据，并对公式注入、HTML 内容和权限作校验；响应为 `private, no-store`。截止且全部评测／评分完成才允许导出，导出入口再次检查，期间重判会返回 409。未完结标记待审核，已完结标记已确认；下载不会自动确认完结。

## 7. 验证与维护

API 回归覆盖草稿保存与审核次数、旧 revision 冲突、选题范围及批量原子性、分数精度、排名完成条件、封榜、阅卷、导出和完结权限。前端验证编辑快照与人数换算边界。

真实数据库浏览器夹具 `TestEventBrowserFixture` 仅绑定回环地址，不能指向生产库。从 `apps/web` 运行 `node tests/e2e/contest-ui-qa.mjs` 检查本轮编辑、选题、奖项和主题；`node tests/e2e/ranking-review-qa.mjs` 覆盖两种场次 × 三种赛制及导出。两组脚本分别从新夹具开始；截图与日志留在忽略提交的 tmp 目录。具体版本验收见 [开发历史](development-history.md)。
