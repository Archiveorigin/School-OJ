## 两条不应机械执行的建议

**不恢复“每题只能有一个待处理工单”的旧索引。** `docs/ticket-feedback.md` 的既有产品规则明确允许同题多份反馈，027 有专门迁移回归测试确认移除。恢复会拒绝合法反馈。实际写入安全由工单 revision 条件更新、题目行锁和 `expected_version_id` 保证；并发处理与过时版本回归测试必须通过。

**不直接增加 `--rm`，也不把所有退出后的观测一并删除。** 正常退出依赖 stderr 中的 cgroup 指标，OOM 还需读取容器状态。CLI 超时退出时容器可能仍运行，此时 `docker exec` 能读取超时瞬间的峰值；正常退出时该调用才必然失败。现在只在 CLI 被取消时读取这份补充快照，并用 defer、信号处理和过期清理完成回收。必须通过 AC/TLE/MLE/RE 真实 Docker 回归，不能以资源自动删除牺牲判题正确性。

## 操作与边界

- **发布**：先备份、校验生产数据副本；轮换既有弱密码并同步服务配置；使用 Git 原始提交字节构建；显式迁移；应用健康后验证判题、认证和前端。数据卷保持原卷，回滚镜像与备份保留。
- **备份**：`BACKUP_ROOT=/opt/School-OJ-backups make backup`。它会短暂停止 Web/API/Worker/MinIO/Redis，完成或失败时恢复原先运行的服务。备份含私有源码和密钥，目录/文件受 umask 077 保护；应复制到受控异地存储。脚本不默认删除旧备份。
- **恢复演练**：`make restore BACKUP=/absolute/path`。只创建 `school-oj-restore-*` 的新卷和容器，数据服务不发布宿主端口；不会启动副本 API/Worker 消费任务。验证后保留恢复项目供检查，清理时仅指定演练项目，不执行全局卷清理。正式切换需要维护窗口和数据写入冻结，禁止直接覆盖在线库。
- **旧版备份凭据**：若备份早于 Redis 认证等必填配置，可设置 `RESTORE_ENV_FILE=/absolute/private.env`，向隔离恢复项目提供完整的新凭据配置；备份原文件和校验清单保持不变。该文件须受权限保护，并保留与备份匹配的数据库名、用户和对象桶名。
- **指标**：只在内部容器网络访问 `api:8080/metrics`、`worker:9091/metrics`；Nginx 外部 `/metrics` 返回 404。Redis 计数是集群总量，抓取多副本时不能重复求和。指标服务支持 Prometheus 文本协议，但本轮未安装 Prometheus/Grafana 或对外告警系统。
- **旧接口**：本轮保留 `/api`。必须从新观测部署后累计完整 30 天；Redis 数据丢失、缺日或分钟缺口均不能认定为零调用。
- **沙箱**：`make sandbox-images` 使用与 worker 同源的 digest。`SANDBOX_MEMORY_MB` 主要是回退限制，题目内存限额仍适用于运行，编译维持既有至少 1 GiB 上限；宿主机需为实际沙箱容器预留资源，worker 自身上限不约束其启动的同级容器。
- **K8s**：当前是要求专用 Docker 节点的参考清单，不承诺支持仅有 containerd 的节点。先在数据依赖可用后运行同配置的 `api --migrate-only` Job，再更新 Deployment；worker 扩容需独立节点和工作根，不能直接提高同节点副本数。
- **颜色存量**：新增 `architecture-colors.json` 明确记录尚未迁移的颜色字面值；它是逐项债务预算，不是目录豁免。已有颜色没有被批量改色；新增样式必须使用语义 token，后续迁移应缩小预算。

## 结构性性能项的处理

保持每用例独立沙箱，避免用例间状态残留。先以用例数量/总预算约束成本，并利用耗时直方图获取证据；若容器启动成本成为瓶颈，应另行实现受控常驻判题服务，在每用例重建进程、工作目录和资源计量边界后再替换当前运行器。

输入文档没有给出“其余十余个列表”“其余 4 处 N+1”的完整定位。本轮修复已确认的团队目录、比赛、题单查询；批量补全本就存在的班级/作业/考试/提交视图不重复改写。其余列表分页应采用与题库一致的 `items/total/page/page_size` 契约、稳定排序和服务端权限过滤，同步调整 OpenAPI 与页面请求；不可直接给旧数组接口追加 LIMIT 而静默截断业务数据。
