# School OJ 架构重构执行清单

## 目标与边界

本轮采用渐进式重构：保留现有 `/api` 与 `/api/v1` 调用链作为兼容层，在 `/api/v2` 建立稳定契约；前端按业务领域抽取请求、类型和可复用交互；后端逐步拆分超大 Handler，并用 Transactional Outbox 消除“提交已入库但判题消息未发送”的一致性缺口。

视觉基准固定为 `docs/design-references/` 下第一版三张考试创建稿，不采用后续生成变体。

## 执行批次

### Batch 1：考试创建与提交可靠性（本轮）

- [x] 抽取 `courses`、`problems`、`exams` 前端 API 模块。
- [x] 抽取考试草稿、题目选择、总分计算和发布校验领域类型与纯函数。
- [x] 将考试创建页拆成基础信息、题目选择、发布确认三个组件化步骤。
- [x] 增加本地草稿保存与恢复，保留 Markdown 导入和批量选题能力。
- [x] 将原始三张视觉稿归档为实现基准。
- [x] 新增 `submission_outbox` 迁移与后台投递器。
- [x] 普通提交、团队提交、人工重判在同一数据库事务内写入 Submission 与 Outbox。
- [x] Worker 继续通过现有租约和状态判断承受至少一次投递语义。
- [x] 前端单元测试与生产构建通过。
- [ ] 真实浏览器设计 QA；当前执行环境未提供可捕获页面与控制台的浏览器表面。

验收条件：数据库提交成功后即使 Redis 暂时不可用，Outbox 仍会重试；考试创建三步主流程可完成；前端类型检查、单测、构建及 API/Worker Go 测试通过。

### Batch 2：契约优先的 `/api/v2`

- [ ] 建立 OpenAPI 单一事实源，先覆盖课程、题目、考试、提交。
- [ ] 生成 TypeScript DTO 与 API Client，替换手写响应结构和页面内路径字符串。
- [ ] 为错误响应、分页、时间、可空字段建立统一 Schema。
- [ ] 旧 `/api`、`/api/v1` 路由增加弃用响应头和访问指标，不立即删除。
- [ ] 增加契约兼容测试，阻止破坏性 Schema 变更进入主分支。

验收条件：第一批页面不再直接调用 Axios；OpenAPI 生成物可重复生成且工作区无差异；旧客户端仍可运行。

### Batch 3：后端题目/考试领域拆分

- [ ] 从 `handlers/server.go` 拆出 `problem`、`exam`、`submission` 路由适配器。
- [ ] 建立 Application Service，Handler 仅处理鉴权上下文、输入绑定和 HTTP 映射。
- [ ] 建立 Repository 接口，集中 GORM 查询、预加载、分页和事务边界。
- [ ] 把考试发布、题目顺序、分值和可见性规则下沉到领域服务。
- [ ] 为每个用例增加服务级测试和 HTTP 合约测试。

验收条件：相关 Handler 不直接访问 DB/Redis；每个用例只拥有一个明确事务边界；`server.go` 不再承载题目/考试业务实现。

### Batch 4：课程/班级领域

- [ ] 抽取课程成员、班级、作业/考试归属公共查询与权限策略。
- [ ] 合并重复的课程选择、成员校验和教师授权逻辑。
- [ ] 前端课程选择器、成员选择器、加载/空状态形成公共组件。

验收条件：课程权限规则有集中测试；页面不重复拼装课程 DTO；课程领域路由无跨域表散落查询。

### Batch 5：团队赛领域

- [ ] 拆分 `teams.go` 的团队、成员、题集、提交用例。
- [ ] 团队提交复用 Submission Service 与 Outbox，不复制判题投递逻辑。
- [ ] 收敛团队角色、可提交条件和比赛时间窗状态机。

验收条件：团队提交和个人提交共享同一条可靠投递链；团队 Handler 不直接操作 Redis。

### Batch 6：Worker 边界与状态机

- [ ] 保留 Worker 直连数据库，但封装 Submission Repository。
- [ ] 明确定义 `queued -> judging -> accepted/failed` 及重试/租约恢复规则。
- [ ] 以 `(submission_id, event_version)` 作为幂等语义并记录重复消费指标。
- [ ] 增加 Redis 重投、Worker 崩溃恢复和超时租约集成测试。

验收条件：重复消息不会产生重复最终结果；状态转换只能通过集中状态机；失败原因具备可观测性。

### Batch 7：视觉系统推广

- [ ] 从考试创建页提炼应用外壳、步骤条、摘要卡、列表工具栏和空状态规范。
- [ ] 建立颜色、间距、字体、圆角和阴影 Token，不让业务页面重复硬编码。
- [ ] 依次迁移题目编辑、考试详情、课程管理和团队赛页面。
- [ ] 每个迁移页面保留桌面、窄屏和关键交互态截图回归。

验收条件：公共组件拥有示例与交互测试；无自造图标或重复视觉常量；关键页面通过设计 QA。

### Batch 8：兼容层下线与治理

- [ ] 基于访问指标发布 `/api`、`/api/v1` 下线时间表。
- [ ] 对外部调用方完成迁移通知和回归验证。
- [ ] 删除无调用旧路由、旧 DTO 和重复 Enqueue 工具。
- [ ] 增加架构约束检查：页面禁止直接 Axios、Handler 禁止跨层访问基础设施。

验收条件：兼容路由连续一个发布周期无调用后再删除；CI 能阻止新的反向依赖和重复接口。

## 每批统一完成定义

1. 行为有自动化测试，错误分支与权限分支不可只测成功路径。
2. 数据库迁移可重复执行，事务边界和回滚路径明确。
3. API 契约已更新并通过生成物一致性检查。
4. 前端通过格式化、类型检查、单测和生产构建。
5. API 与 Worker 通过 `go test ./...`，关键异步路径补集成测试。
6. 涉及视觉变化时必须完成同视口、同状态的截图比较；无法捕获时明确标记阻塞。
