# 功能说明

## 1. 账号与个人中心

系统支持注册、登录、邮箱验证码、忘记密码和密码重置。登录用户可以维护个人资料、头像、密码和邮箱，也可以提交反馈或注销账号。

前端会恢复登录状态，并检查是否存在进行中的强制考试。认证信息通过 Bearer Token 发送，私有资源下载和 SSE 事件流同样使用认证请求。

## 2. 角色与权限

### 2.1 基础角色

| 角色 | 主要能力 |
| --- | --- |
| 学生 `student` | 加入课程和班级、完成练习/作业/考试、参加团队活动、查看自己的提交 |
| 教师 `teacher` | 管理授权课程、班级、作业和考试，查看报表、人工阅卷和发起查重 |
| 管理员 `admin` | 拥有教师能力，并管理用户、权限、工单、审计和系统级资源 |

课程成员还可具有课程管理员或课程助教身份；这些身份用于课程范围内授权，不替换用户基础角色。

### 2.2 出题者权限

“出题者”是独立附加权限 `can_author`，可与学生、教师、管理员基础角色并行。普通用户可提交出题资格申请，管理员在“用户与权限 → 权限管理”中审核、授予或收回。管理员天然具备出题能力。

权限接口采用可扩展权限定义，后续新增附加权限时不需要把它们塞入基础角色枚举。

### 2.3 团队角色

团队内部角色为所有者、管理员和成员。团队可以配置比赛内容由所有成员、管理员以上或仅所有者维护；系统管理员可执行系统级治理操作。

## 3. 题库、题目版本与工单

### 3.1 公共题库

题库首页提供题号/标题/标签搜索、难度、多算法标签、个人完成状态、分页、结果总数和筛选重置。多个标签采用 OR 匹配；算法、时间和来源标签统一使用弹出式多选组件。

桌面端显示高密度题目表，移动端显示压缩题目卡片。通过率只统计已完成评测中的 Accepted 比例，不把排队、运行或系统错误计入分母。

题目详情包含题面、限制、元数据、提交入口、测试资料下载权限和本题提交记录。题面图片通过版本化资源接口加载。

### 3.2 不可变版本

每个题目具有一个当前版本，历史版本只读保留。普通练习提交绑定提交当时的当前版本；考试和团队比赛在关联题目时绑定明确版本；重判继续使用提交原版本。

题目替换后：

- 公共题库切换到新版本；
- 未开始的考试和比赛同步更新；
- 已开始或已结束场次保持原版本；
- 历史提交、作业和归档题目的访问关系不被破坏。

### 3.3 工单修改

工单是题目写操作的唯一入口，支持：

- `create`：新增题目；
- `replace`：覆盖替换题面、限制、题包或测试点；
- `archive`：归档题目，从公共目录和后续选题入口隐藏。

工单状态为待处理、处理中、已完成、已驳回、已取消。出题人只能替换或归档自己拥有的题目；同一题目同一时间只能存在一个未完成的替换或归档工单。

每个工单都必须包含修改说明和参考附件。替换、归档明确采用覆盖性操作；新增或替换在管理员执行时必须上传最终完整题包。附件只允许申请人和管理员下载。

目标范围可以是公共题库、预备题库或指定团队题单。管理员在后台查看工单详情、影响场次和附件，随后执行或驳回；工单管理不再混合出题资格审批。

## 4. 提交与在线判题

系统支持 C、C++、Python 和 Java。编辑器按用户和业务上下文恢复最近代码，避免不同账号、考试、比赛或题单之间串用草稿。

提交经过 Redis Streams 进入 Worker，状态通过 SSE 实时更新。详情页展示语言、时间、内存、源码和允许公开的测试点结果；代码复制保留精确文本。

答案比较支持精确比较、令牌比较和浮点误差比较。判题沙箱与资源限制详见 [安全设计](security.md)。

## 5. 课程、班级与作业

教师和管理员可以创建、编辑和归档课程与班级，维护课程成员，批量导入或移除学生。学生可以通过邀请码预览并加入课程/班级，也可以加入多个班级并切换学习上下文。

课程空间包含课程概况、作业和考试。作业绑定课程、班级和题目，学生在规定范围内提交；教师可查看完成情况和成绩报告。

归档采用保留历史关系的逻辑操作，避免破坏已经产生的提交和统计。

## 6. 校内考试

### 6.1 创建与发布

后台考试创建采用三个步骤：

1. 基本信息：课程、班级、标题、说明和时间；
2. 题目与分值：选择已存在题目及其版本，配置顺序和满分；
3. 发布确认：复核赛制、题目、总分、时间和封榜配置。

浏览器可保存未完成草稿。旧 `/exams/new` 地址兼容跳转到 `/admin/exams/new`。

### 6.2 考试页面

考试详情保留考试专属子页面：概览、考试题目、提交代码、提交记录和实时榜单。教师和管理员可查看考试报表、导出成绩、人工触发评测，并对人工评阅考试给分。

强制考试模式会限制学生离开当前考试，学生也可以主动交卷。是否允许提交由开始时间、结束时间和交卷状态共同决定。

### 6.3 赛制

| 赛制 | 计分与可见性 |
| --- | --- |
| OI | 每题取最后一次提交；结束前不显示排行榜和具体评测结果，结束后公开 |
| IOI | 每题取最高分；按总分、满分题数和最后有效得分时间排序 |
| ACM | 按通过题数和罚时排序；首次通过时间加通过前每次有效错误提交 20 分钟 |

IOI 和 ACM 可以开启封榜，默认封榜时长为 60 分钟且必须短于考试时长；没有结束时间的考试不能封榜。组织者在封榜期仍能查看实时数据。

## 7. 团队、比赛与团队题单

### 7.1 团队

用户可以查看自己的团队和公开团队、创建团队、申请加入、退出团队。团队所有者和管理员处理成员申请、调整成员角色、移除成员并维护团队资料与内容权限。

### 7.2 团队比赛

团队比赛经历草稿、已发布、进行中和已结束四个状态。草稿期可以调整信息和题目；发布后冻结题目集合、题目版本、参赛人员范围和赛制；进行中按时间窗开放提交。

比赛使用真实子路由：

- `/contest/:contestId/description`：比赛说明、状态、赛制、时间和组织信息；
- `/contest/:contestId/problems`：场内题号、题名、满分和允许公开的个人状态；
- `/contest/:contestId/problems/:label`：题面、A/B/C 导航、提交入口和本题记录；
- `/contest/:contestId/scoreboard`：IOI 或 ACM 排行榜。

旧 `#overview`、`#problems`、`#records`、`#ranking` 地址保留兼容跳转。提交记录移动到对应题目页，不再作为比赛顶层菜单。

比赛和考试共用同一套排行榜组件、筛选、奖项标识和移动端横向滚动行为。OI 不显示排行榜入口；IOI/ACM 支持封榜并由服务端脱敏。

### 7.3 团队题单

团队题单把公共题目按关联顺序展示为字母题号，支持题面内切换、代码提交、筛选提交记录和讨论。所有请求都携带题单上下文，结果不会跳转或泄漏到其他团队空间。

## 8. 管理后台

后台沿用统一布局，并按职责分组：

| 模块 | 主要功能 |
| --- | --- |
| 教学概览 | 核心教学指标、近期考试、待办事项、快捷入口和最近活动 |
| 课程管理 | 课程生命周期和课程成员 |
| 班级管理 | 班级生命周期、学生和批量导入 |
| 考试管理 | 创建、查看、删除、报表、导出和阅卷 |
| 预备题库 | 查看未公开题目和只读题包信息，写操作进入工单 |
| 工单管理 | 只处理题目新增、替换和归档工单 |
| JPlag 查重 | 创建任务、查看状态和报告 |
| 用户与权限 | 用户列表、基础角色、密码重置和可扩展附加权限 |
| 审计日志 | 查询关键资源和权限操作 |

管理员专属接口不会因为教师共享后台布局而扩大授权。首页统计只展示真实接口数据或明确空状态，不伪造数量和活动。

## 9. 查重与审计

教师和管理员可以按课程任务创建 JPlag 查重作业并查看报告。未配置原生 JPlag 时使用轻量后备算法保证流程可测试；正式环境应配置固定版本 JAR。

用户、权限、课程、比赛、工单和其他关键变更写入审计日志，供管理员追踪操作人、资源和时间。

## 10. 兼容入口

- API 同时注册 `/api` 和 `/api/v1`。
- 旧题目写接口返回工单入口提示，不直接修改数据。
- 旧题目审批记录迁移为历史工单。
- 旧赛制值 `score` 自动解释为 IOI，`penalty` 自动解释为 ACM。
- 旧课程、班级、考试、后台和团队比赛地址通过前端重定向进入当前页面。
