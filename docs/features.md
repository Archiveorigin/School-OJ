# 功能说明

## 1. 账号与个人中心

系统支持注册、登录、邮箱验证码、忘记密码和密码重置。登录用户可以维护个人资料、头像、密码和邮箱，也可以提交反馈或注销账号。

前端会恢复登录状态，并检查是否存在进行中的强制考试。认证信息通过 Bearer Token 发送，私有资源下载和 SSE 事件流同样使用认证请求。

## 2. 角色与权限

### 2.1 基础角色

| 角色 | 主要能力 |
| --- | --- |
| 学生 `student` | 加入课程和班级、完成练习/作业/考试、参加团队活动、查看自己的提交 |
| 教师 `teacher` | 管理授权课程、班级、作业和考试，查看报表、人工阅卷和发起查重 |
| 管理员 `admin` | 保留管理员身份，按明确能力管理用户、权限、工单、审计及资源；新增操作不自动放行 |

课程成员还可具有课程管理员或课程助教身份；这些身份用于课程范围内授权，不替换用户基础角色。

### 2.2 出题者权限

“出题者”是独立附加权限 `can_author`，可与学生、教师、管理员基础角色并行。普通用户可提交出题资格申请，管理员在“用户与权限 → 权限管理”中审核、授予或收回。当前授权基线给管理员内置出题能力，具体权限按服务端能力表判断。详见 [权限规则](authorization.md)。

权限接口采用可扩展权限定义，后续新增附加权限时不需要把它们塞入基础角色枚举。

### 2.3 团队角色

团队职级严格为三级：创建者（`owner`）、管理员（`admin`）、团员（`member`），不改变学生/教师/系统管理员的基础账号身份。创建者可任免团队管理员，管理员可审核申请、移除团员，但不能移除创建者或其他管理员。创建者不可直接退出或被移除；系统管理员保留系统级治理权限。团队可另外配置比赛内容由全体团员、管理员以上或仅创建者维护。

## 3. 题库、题目版本与工单

### 3.1 公共题库

题库首页提供题号/标题/标签搜索、难度、多算法标签、个人完成状态、分页、结果总数和筛选重置。多个标签采用 OR 匹配；算法、时间和来源标签统一使用弹出式多选组件。

桌面端显示高密度题目表，移动端显示压缩题目卡片。通过率只统计已完成评测中的 Accepted 比例，不把排队、运行或系统错误计入分母。

题目详情包含题面、限制、元数据、提交入口、测试资料下载权限和本题提交记录。题面图片通过版本化资源接口加载。

### 3.2 不可变版本

每个题目具有一个当前版本，历史版本只读保留。普通练习提交绑定提交当时的当前版本；考试和团队比赛在关联题目时绑定明确版本；重判继续使用提交原版本。

题目替换后：

- 公共题库切换到新版本；
- 所有场次保留已绑定版本，草稿／退回状态可明确采用最新版本；
- 已开始或已结束场次保持原版本；
- 历史提交、作业和归档题目的访问关系不被破坏。

### 3.3 工单修改

公共／预备题库的新增、替换、归档通过工单执行；另支持建议与考试、比赛反馈。修改和建议面向登录用户，新增与删除申请需要出题资格。材料不足可退回补充，作者在原单补充后重提；同题允许多份反馈。

管理员可直接校验所选工单材料并在线组包，完整 ZIP 为可选入口。原附件保持私有，场次反馈允许所属管理者在授权范围查看和处理。状态、附件、并发与执行规则见 [工单工作流](tickets.md)。独立场次草稿使用 [组题工作区](events.md)，不直接发布到题库。

## 4. 提交与在线判题

系统支持 C、C++、Python 和 Java。编辑器按用户和业务上下文恢复最近代码，避免不同账号、考试、比赛或题单之间串用草稿。

提交经过 Redis Streams 进入 Worker，状态通过 SSE 实时更新。提交弹窗以紧凑文本展示结果短标识（AC、WA 等）、时间、内存、语言和通过用例数。用例总数读取提交绑定版本的完整测试集，不根据遇错即停的结果行数推算；排队、运行、人工评阅和隐藏结果显示“—”。随主题切换的代码框提供左侧行号、绿色分隔线和代码区域右上角的复制按钮；按钮不遮挡源码，长行可横向滚动，复制保留原始代码、不含行号。

全局提交、题库练习、作业、考试、团队比赛及团队题单的详情统一使用 `SubmissionDetailDialog → SubmissionDetailContent → SourceCodeViewer`。人工阅卷复用同一详情内容，保留参考判题和评分操作。团队管理员只能查看本团队范围的提交；普通团员仅有本人详情权限，公开题目的作者身份不能绕过团队边界。

答案比较支持精确比较、令牌比较和浮点误差比较。判题沙箱与资源限制详见 [安全设计](security.md)。

## 5. 课程、班级与作业

教师和管理员可以创建、编辑和归档课程与班级，维护课程成员，批量导入或移除学生。学生可以通过邀请码预览并加入课程/班级，也可以加入多个班级并切换学习上下文。

课程空间包含课程概况、作业和考试。作业绑定课程、班级和题目，学生在规定范围内提交；教师可查看完成情况和成绩报告。

归档采用保留历史关系的逻辑操作，避免破坏已经产生的提交和统计。

## 6. 校内考试

### 6.1 创建与发布

后台考试创建采用三个步骤：

1. 基本信息：课程、班级、标题、说明和时间；
2. 题目与分值：选择已存在题目及其版本，配置顺序和满分；
3. 保存草稿：复核配置后进入组题工作区，提交整场审核，审核通过才按时间开放。

浏览器可保存未完成草稿。旧 `/exams/new` 地址兼容跳转到 `/admin/exams/new`。

### 6.2 考试页面

考试与团队比赛复用公共页头、导航、题目列表和题面布局，但保留独立数据适配器、权限和提交上下文：

- `/exams/:id/description`：考试说明、时间、赛制、评阅方式。
- `/exams/:id/problems`：独立题号、题名、分值和可展示的个人状态。
- `/exams/:id/problems/:label`：以 `B.特殊扫雷` 为一级标题，提供题面、题号导航、提交和本题记录。
- `/exams/:id/scoreboard`：允许公开的 IOI/ACM 榜单；OI 无入口。

旧 overview、ranking 分别跳转说明、排行榜；旧 submit、records 有 label 或 problem_id 时定位题目，否则进入题目列表。旧四个专属内容组件已删除，教师报表、导出、人工评阅和交卷保留。

学生必须确认进入正在进行的考试，普通详情 GET 不再隐式入场。入场后服务器动态锁定当前账号，只允许本场考试、本人本场提交和身份会话请求；刷新、重新登录或同账号多标签页会恢复限制。交卷或到达截止时间后解除限制；进行中提前交卷者保持原访问限制，截止后原范围内人员可以只读题面、附件和本人提交，所有人均不能再提交。管理员确认完结后进入鉴权归档。详见 [场次工作流](events.md)。

前端记录离开/返回窗口，合并焦点和可见性重复事件，返回时保留警告；拦截 F12 和常见开发者工具快捷键，不禁止正常复制粘贴、不强制全屏、不自动扣分或交卷。教师在考试管理的“行为日志”中按学生、事件和时间分页查询记录。匿名公开题库仍可访问，详见 [安全边界](security.md#7-考试权限与行为日志)。

### 6.3 赛制

| 赛制 | 计分与可见性 |
| --- | --- |
| OI | 每题取最后一次提交；赛中隐藏具体评测结果；参与者不提供排行榜入口，管理端按原权限查看 |
| IOI | 每题取最高分；按总分、满分题数和最后有效得分时间排序 |
| ACM | 按通过题数和罚时排序；首次通过时间加通过前每次有效错误提交 20 分钟 |

IOI 和 ACM 可以开启封榜，默认封榜时长为 60 分钟且必须短于考试时长；没有结束时间的考试不能封榜。组织者在封榜期仍能查看实时数据。

## 7. 团队、比赛与团队题单

### 7.1 团队

用户可以查看自己的团队和公开团队、创建团队、申请加入、退出团队。私有团队不进入公开发现列表，加入页只展示准入所需信息，流程按模式分开：

| 加入模式 | 加入者操作 | 管理端分享方式 |
| --- | --- | --- |
| 邀请制 | 从 `/teams/join` 输入邀请码，预览团队后确认加入；无需先取得团队链接，也不要求再次输入邀请码 | 复制邀请码 |
| 申请制 | 直接打开 `/teams/:teamSlug/join` 提交申请；也可在 `/teams/join` 的“链接申请”粘贴申请链接，等待管理员审批 | 复制申请链接 |
| 自由加入 | 打开加入页确认加入 | 复制加入链接 |

邀请码校验去除首尾空格、忽略大小写，仅放在请求体中，不写入 URL 或浏览器存储。旧邀请链接仍可进入原加入页输入邀请码。重复或已失效的邀请码不返回任意团队信息；团队模式改变后按当前模式处理，旧待审状态不会阻挡邀请或自由加入。

邀请码只返回给有团队管理权限的用户，普通成员和访客不可读取。所有者和系统管理员可调整成员职级，团队管理员可审核申请及移除普通成员。加入、审核、退出、移除和职级变更使用同一团队行锁；重复加入不覆盖角色，相反审批结果返回 409，重放已批准申请不让被移除成员重新入组。驳回后可重申，退出后可重入，直接加入会结束遗留待审申请，已删除账号不能加入。

### 7.2 团队比赛

团队比赛经历草稿／退回、待审核、未开始、进行中、已截止、已完结。草稿可调整题目与奖项比例，支持人数单位换算；换算基数来自本场“排名与评奖名单”，默认全体成员，可逐人选择或导入 UTF-8 TXT／CSV 用户名名单（去重、未知或重名需先修正），名单不限制团队成员参加或提交。待审核内容锁定，审核通过后按时间开放。截止保留只读资源，评测全部完成后显示最终排名，管理员确认完结才归档。完整权限、版本和奖项取整规则见 [场次工作流](events.md)。

比赛使用真实子路由：

- `/contest/:contestId/description`：比赛说明、状态、赛制、时间和组织信息；
- `/contest/:contestId/problems`：场内题号、题名、满分和允许公开的个人状态；
- `/contest/:contestId/problems/:label`：题面、A/B/C 导航、提交入口和本题记录；
- `/contest/:contestId/scoreboard`：IOI 或 ACM 排行榜。

旧 `#overview`、`#problems`、`#records`、`#ranking` 地址保留兼容跳转。提交记录移动到对应题目页，不再作为比赛顶层菜单。

比赛和考试共用同一套排行榜组件、筛选、奖项标识和移动端横向滚动行为。OI 不显示排行榜入口；IOI/ACM 支持封榜并由服务端脱敏。

### 7.3 团队题单

团队题单包含公共题目和本团队授权私有题目，按关联顺序展示为字母题号，支持题面内切换、代码提交、筛选提交记录和讨论。所有请求都携带题单上下文，结果不会跳转或泄漏到其他团队空间。

## 8. 管理后台

后台沿用统一布局，并按职责分组：

| 模块 | 主要功能 |
| --- | --- |
| 教学概览 | 核心教学指标、近期考试、待办事项、快捷入口和最近活动 |
| 课程管理 | 课程生命周期和课程成员 |
| 班级管理 | 班级生命周期、学生和批量导入 |
| 考试管理 | 创建、查看、删除、报表、导出和阅卷 |
| 预备题库 | 查看未公开题目和只读题包信息，写操作进入工单 |
| 工单管理 | 题目新增、替换、归档、建议及场次反馈；支持退回补充 |
| JPlag 查重 | 创建任务、查看状态和报告 |
| 用户与权限 | 用户列表、基础角色、密码重置和可扩展附加权限 |
| 审计日志 | 查询关键资源和权限操作 |

管理员专属接口不会因为教师共享后台布局而扩大授权。首页统计只展示真实接口数据或明确空状态，不伪造数量和活动。

## 9. 查重与审计

教师和管理员可以按课程任务创建 JPlag 查重作业并查看报告。未配置原生 JPlag 时使用轻量后备算法保证流程可测试；正式环境应配置固定版本 JAR。

用户、权限、课程、比赛、工单和其他关键变更写入审计日志，供管理员追踪操作人、资源和时间。

## 10. 兼容入口

- API 同时注册 `/api` 和 `/api/v1`。
- 旧题目写接口返回工单入口提示，不直接修改数据。
- 旧题目审批记录迁移为历史工单。
- 旧赛制值 `score` 自动解释为 IOI，`penalty` 自动解释为 ACM。
- 旧课程、班级、考试、后台和团队比赛地址通过前端重定向进入当前页面。
