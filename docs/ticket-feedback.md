# 工单反馈与发布验收

本次基线：`f839ff9`；功能分支：`codex/ticket-feedback-20260923`。

## 业务与入口

- 修改、建议面向所有登录用户。新增、删除题目申请需要出题资格，系统管理员保留权限。
- 普通题目页、团队题单的题目页通过「工单修改」打开本题面板；游客可以查看公开正文，提交时登录。个人页保留「我的工单」，出题用户可「新增题目」，全局导航移除工单入口。
- 考试、比赛整体及本题反馈在当前页打开。课程管理者、团队管理者从同一入口查看本场工单。考试管理完成情况中的入口同样绑定考试。
- 工单列表统一显示编号、类型、用户名、说明、附件数量、状态、时间、操作，支持类型／状态过滤；系统管理列表另有所属对象过滤，服务端分页。
- 申请人可编辑、软删除本人待处理工单；处理后只读。删除工单不会删除题目，题目删除申请由管理员执行归档。
- 建议和场次整体反馈填写处理结果后完成；驳回必须说明原因。新增／修改题库由系统管理员上传最终完整 ZIP 题包，申请附件只供参考。
- 新题必须包含标题和 Markdown 题面。桌面左右对照，手机编辑／预览切换，复用公式、代码渲染；原始 HTML 禁用。草稿未审核时不写入题库。

流程参考 [洛谷官方工单状态说明](https://help.luogu.com.cn/manual/luogu/ticket)，按已确认需求采用查看、完成／执行、驳回，不引入指派、待补充或挂起。

## 接口与隔离

现有 `/api/problem-change-tickets` 及 `/api/v1` 同名入口保留；新增 PATCH、DELETE、`resolve`、多附件访问。列表改为 `{ items, total, page, page_size }`，旧单附件下载路径 `/problem-change-tickets/:id/attachment` 保留。

所属对象入口：

| 范围 | 基础路径 |
| --- | --- |
| 普通题目 | `/problems/:id/change-tickets` |
| 考试 | `/exams/:id/change-tickets` |
| 比赛 | `/contests/:contest_id/change-tickets` |

各范围提供列表、创建、详情、修改、删除、附件、撤回、完成、驳回。OpenAPI 与生成客户端同步更新，前端按上下文选择操作。

普通题目的新反馈正文在题目原有访问范围内公开，附件仅申请人和系统管理员访问。考试／比赛工单及附件仅申请人、所属管理者和系统管理员访问，结束后也不公开；「允许成员组织比赛」不等于允许查看他人工单。历史工单默认私有。

每次列表、详情、修改、删除和文件访问都重新校验范围及权限。考试期间仅当前考试的工单路径列入白名单，个人工单、普通题目、其他考试和全局附件地址均被阻止。题目版本从考试／比赛关联记录读取，客户端不能指定其他范围或版本。响应只投影所需信息，不返回完整用户／题目模型或存储路径。

附件最多 20 个，单个 32 MiB，总计 96 MiB；实际读取量受限，上传失败或保存冲突会清理未引用对象。附件不自动解压或执行。PNG、JPEG、GIF 预览校验实际类型和图片尺寸，经鉴权接口加载为临时 blob URL；场次面板没有外跳链接。

编辑、删除、处理及执行需要 `revision`；题库执行另需核对 `expected_version_id`。版本冲突返回 409。题库更新创建不可变版本，只更新未开始场次；已开始场次和历史提交仍指向原版本。

## 本地复验

API 与 Worker 的集成测试必须连接专用本地测试数据库和 Redis：

```powershell
$env:GIN_MODE = 'release'
$env:OJ_TEST_DATABASE_URL = 'host=127.0.0.1 port=55439 user=ojtest dbname=oj_exam_security_test sslmode=disable'
$env:OJ_TEST_REDIS_ADDR = '127.0.0.1:56379'
# 分别在 apps/api、apps/worker 执行
go test ./... -count=1 -json
# apps/web
npm run test -- --run
npm run build
```

测试使用隔离 schema；不得连接生产数据库。API 测试涵盖多角色访问、跨场次／课程／团队、私有附件、旧附件路径、并发处理、题包失败、历史版本保持和附件失败清理。生产构建同时运行接口契约检查、生成客户端一致性检查及 TypeScript 检查。

真实浏览器验收：在 `apps/api` 设置 `OJ_TICKET_BROWSER_FIXTURE_ADDR=127.0.0.1:18087`，运行 `go test ./internal/handlers -run '^TestTicketBrowserFixture$' -count=1 -v -timeout=90m`；将生产 Web 预览绑定 `127.0.0.1:4177`，代理 `/api` 到 `127.0.0.1:18087`，随后在 `apps/web` 执行 `npm run qa:tickets`。每轮使用新 fixture，避免已交卷状态影响复验。不要指向生产系统。

验收使用 1440×1100、390×844，覆盖游客入口、个人页、题目多附件／编辑／删除、公开正文与附件私有、新题公式／代码／图片实时预览、管理完成／驳回、比赛和考试整体／本题反馈、考试跨范围拒绝、题包执行与归档。截图和 JSON 报告生成在忽略提交的 `tmp/ticket-feedback-qa/`。

本机使用 PostgreSQL 18、Redis 和 S3 HTTP 测试服务；S3 测试服务不是 MinIO。Docker Engine 当前不可用，Docker 沙箱测试的跳过不计为通过；PostgreSQL 16、真实 MinIO、实际应用镜像需在服务器隔离环境补验。

## 发布闸口

1. 本地功能和验收完成后，展示差异、截图、测试结果、拟提交清单，等待维护者手动确认，再使用本机 Git 提交。
2. 不提交四个原有脚本改动和本地 `MEMORY.md`；保留管理页已移除统计卡片的改动。
3. 推送部署远端功能分支，记录旧提交和 API／Worker／Web 镜像，备份数据库及相关私有对象。生产数据服务和数据卷保持不变。
4. 在服务器独立 Compose 项目、独立测试库和对象桶验证 PostgreSQL 16、MinIO 和新镜像；通过后才快进部署分支，重建并替换 API、Worker、Web。
5. 验证健康检查、日志、登录、工单权限、附件及考试／比赛隔离。仅清理核实属于本项目的无用容器和镜像，保留数据卷和回滚镜像。
6. 服务器通过后，使用本机 Git 将同一提交推送到 GitHub 同名分支，不强推、不合并主分支。
