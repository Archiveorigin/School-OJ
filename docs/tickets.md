# 题目工单与反馈工作流

本文件维护当前工单规则；历史需求、曾经的 ZIP 必填规则和发布证据统一见 [开发历史](development-history.md)。场次独立组题见 [场次工作流](events.md)，不与题库工单混用。

## 1. 入口与权限


- 修改、建议面向所有登录用户。新增、删除题目申请需要出题资格，系统管理员保留权限。
- 普通题目页、团队题单的题目页通过「工单修改」打开本题面板；游客可以查看公开正文，提交时登录。个人页保留「我的工单」，出题用户可「新增题目」，全局导航移除工单入口。
- 考试、比赛整体及本题反馈在当前页打开。课程管理者、团队管理者从同一入口查看本场工单。考试管理完成情况中的入口同样绑定考试。
- 工单列表统一显示编号、类型、用户名、说明、附件数量、状态、时间、操作，支持类型／状态过滤；系统管理列表另有所属对象过滤，服务端分页。
- 申请人可编辑、软删除本人待处理／待补充工单；补充后原单重新进入待处理，终结后只读。删除工单不会删除题目，题目删除申请由管理员执行归档。
- 建议及场次反馈可填写处置结果后完成；驳回和退回补充必须说明原因。新增／修改题库由系统管理员核对工单材料在线组包，完整 ZIP 为可选方式。
- 新题必须包含标题和 Markdown 题面。桌面左右对照，手机编辑／预览切换，复用公式、代码渲染；原始 HTML 禁用。草稿未审核时不写入题库。

## 接口与隔离

现有 `/api/problem-change-tickets` 及 `/api/v1` 同名入口保留；新增 PATCH、DELETE、`resolve`、多附件访问。列表改为 `{ items, total, page, page_size }`，旧单附件下载路径 `/problem-change-tickets/:id/attachment` 保留。

所属对象入口：

| 范围 | 基础路径 |
| --- | --- |
| 普通题目 | `/problems/:id/change-tickets` |
| 考试 | `/exams/:id/change-tickets` |
| 比赛 | `/contests/:contest_id/change-tickets` |

各范围提供列表、创建、详情、修改、删除、附件、撤回、完成、驳回。OpenAPI 与生成客户端同步更新，前端按上下文选择操作。

普通题目的新反馈正文在题目原有访问范围内公开，附件仅申请人和系统管理员访问。考试／比赛工单及附件仅申请人、所属管理者和系统管理员访问，结束后也不公开；「允许成员组织比赛」不等于允许查看他人工单。历史工单默认私有。

每次列表、详情、修改、删除和文件访问都重新校验范围及权限。考试期间仅当前考试的工单路径列入白名单，个人工单、普通题目、其他考试和全局附件地址均被阻止。题目版本从考试／比赛关联记录读取，客户端不能指定其他范围或版本。响应只投影所需信息，不返回完整用户／题目模型或存储路径。

修改说明为 4 至 10000 个 Unicode 字符（去除首尾空白后计数）。新增题目附件最多 30 个，其他类型最多 20 个；编辑时保留附件与新上传附件合并计数，编辑器显示已选择数量。单个 32 MiB、总计 96 MiB 的限制不变；实际读取量受限，上传失败或保存冲突会清理未引用对象。新增工单的 ZIP 会流式检查文件路径、CRC、解压大小与同名 `.in/.out` 配对，最多 1024 个条目，不落盘解压或执行；原 ZIP 作为一个私有附件保存。PNG、JPEG、GIF 预览校验实际类型和图片尺寸，经鉴权接口加载为临时 blob URL；场次面板没有外跳链接。


## 2. 材料、补充与执行


新增题目：作者填写规范题面并上传材料 → 管理员选择材料、校验与预览 → 执行入库并完成。材料不足则退回补充 → 作者修改并重新提交。驳回仍表示最终不采纳，已完成／已驳回工单不允许重写。

算法标签由管理员在入库审核区通过已有标签选择器多选；后续修改自动载入现有标签，清空选择会明确清除标签。作者提交新增工单的界面目前不提供标签预选。

修改题目：管理员从当前版本编辑题面和参数，保留未替换的数据；附件中的测试集合必须显式确认替换，不能静默覆盖。新增的测试点按等权计分，保留的测试点维持原权重；自定义权重可使用完整题包方式。

删除题目仍执行归档，保留版本、场次和历史提交。建议、场次整体反馈以及场次本题修改反馈可以记录处置结果完成，不能冒充已经执行题库变更。题库执行仍校验工单修订号与当前版本，不自动更换任何场次绑定版本及历史提交；成功后提供题目入口。

附件沿用新增 30 个、其他 20 个，单个 32 MiB、合计 96 MiB。所选 ZIP 展开材料合计最多 96 MiB，单包最多 1024 条目，拒绝特殊文件、越界路径和重复来源。题面图片沿用现有题包限制（单个 5 MiB、合计 20 MiB），不符合要求时可退回压缩。参考文件可以留在工单中，但不勾选入库。用户原附件始终私有，正式题目资源使用原有权限接口。

## 复用与可靠性

- 复用 `BuildProblemPackage` / `RebuildProblemPackage`、图片验证、对象存储、题目版本事务、固定题面编辑器、实时预览和 `mapConcurrent`；不增加依赖或第二套判题系统。
- 材料按 ID、文件名及路径用映射表查找、去重和配对，排序后稳定生成测试点；不在前端读取全部测试文件内容。
- 重型组包最多并发两次，私有图片最多并发三个读取；预检不写题库或对象，执行仍重新校验材料及版本。
- 列表只投影摘要，不返回完整题面、附件明细与审核历史，也不逐项查询执行影响统计；打开详情时再加载。
- 原工单状态转换、处理记录和修订号在同一更新／事务中提交，重复执行返回冲突；失败回收新上传对象，既有版本不受影响。
- 迁移 `029_ticket_workflow.sql` 添加历史记录列并扩展状态约束，不改已有迁移。回滚程序前应暂停工单写入，旧程序不能完整处理待补充状态。

## 验证方法

`npm run qa:ticket-workflow` 在两个视口验证缺失材料提示、退回、重提、101 组测试点与中文图片直接入库，以及只改题面后仍保留测试点与图片。`npm run qa:tickets` 回归原有工单、考试／比赛隔离、旧 ZIP 入库和归档；`npm run qa:ticket-import` 回归导入、慢网络和题单功能。全部交互仅运行在隔离测试环境。

数据库集成覆盖附件去重、空测试点、补充前禁止执行、修订号冲突、原题数据保持、范围改动权限及终结状态不可编辑。


## 3. 并发、版本与数据保护

同一题目允许多张反馈工单，不恢复已由迁移 027 移除的未完成工单唯一索引。编辑、删除、退回、处理与执行核对 `revision`；题库执行另外核对 `expected_version_id`，使用题目行锁及事务完成写入。过时操作返回 409，不能覆盖新版本。

题库新增／替换生成不可变版本，既有场次不会自动换题；仅在可编辑的场次工作区主动采用最新版本。场次本题反馈可以记录处置后关闭，但结单不等于已改测试点或完成重判。

新增题目使用固定栏目编辑器。题面、输入、输出、至少一组样例必填，提示可选；兼容旧草稿时先放入描述栏并提示整理，不自动提交改写。题库执行优先使用所选工单材料在线组包，完整 ZIP 是可选方式。详细材料结构与比较器见 [题目包规范](problem-package.md)。
