# 开发历史：用户提示词与验收记录

本文件是开发历史的唯一入口。每个日期记录属于当时版本，不代表当前行为；现行规则从 [文档导航](index.md) 查阅。未保存逐字提示词的历史只记需求摘要，不伪造用户原话。测试数字、依赖扫描和生产状态只适用于记录日期。

## 早期阶段（原始提示词未保存）

以下为基础平台至 2026-09-18 的既有需求／实现摘要及当时验收。早期“未开始场次自动换版”“截止即隐藏”“直接发布”等描述已被后续整场审核与版本固定规则替代。


## 1. 基础平台阶段

项目最初建立 API、Worker、Web 三应用结构，完成用户、课程、班级、题库、作业、考试和基础排行榜，并使用 PostgreSQL、Redis、MinIO 和 Docker 组成可独立部署的学校 OJ。

随后补充个人资料、注册找回、邮件验证、审计日志和 JPlag 工作流，使平台从单纯判题服务扩展为完整教学系统。

## 2. 判题可靠性与安全阶段

主要演进包括：

- Redis Streams 消费组和 pending 任务回收；
- 每提交可续期租约和幂等状态判断；
- 提交与 Transactional Outbox 同事务写入；
- 状态、测试点和进度的事务性最终写入；
- SSE 实时通知与低频对账；
- cgroup CPU/峰值内存计量和 OOM 识别；
- Docker 禁网、只读根、非 root、capability、seccomp、pids 和输出限制；
- 精确、令牌和浮点误差三种内置比较器。

这些能力最终形成当前统一判题链，普通练习、作业、考试、团队比赛和题单不再维护不同的判题实现。

## 3. 教学与团队阶段

课程和班级从简单列表扩展为课程空间，支持多班级加入、课程邀请码、成员管理、作业与考试上下文。

团队功能经历了团队入口、成员权限、题单、比赛生命周期、场内字母题号、上下文提交和排行榜的逐步完善。比赛从页面内 Hash 标签改为真实子路由，并明确与校内考试的业务边界。

## 4. 排行榜演进

早期系统使用 `score` 和 `penalty` 两种内部值，并分别维护考试、比赛及独立排行榜页面。之后抽取了共享排行榜组件、排序适配器、奖项比例、固定列和移动端横向滚动。

当前业务统一为 OI、IOI、ACM：

- 旧 `score` 数据迁移为 IOI；
- 旧 `penalty` 数据迁移为 ACM；
- OI 增加最后提交计分和赛中严格隐藏；
- IOI/ACM 增加封榜；
- 团队比赛放弃独立视觉，完全复用考试排行榜；
- 无路由的独立排行榜页面和旧版视觉规格已删除。

组件内部仍可能使用 `score`、`penalty` 作为两类表格适配名称，它们是展示层兼容术语，不是对外赛制选项。

## 5. 题目管理演进

题目最初支持页面直接创建、编辑、删除、测试点替换和审批。随着考试和比赛场景增加，直接覆盖题目会改变已开始场次的内容，因此后来完成以下重构：

1. 新增不可变 `problem_versions`；
2. 考试题目、比赛题目和提交绑定版本；
3. 旧题包生成版本 1 并回填历史关系；
4. 所有写操作收口为题目工单；
5. 替换只同步未开始场次，历史场次保持原版本；
6. 删除改为归档，保留历史引用；
7. 工单参考附件改为必填，替换和归档明确采用覆盖操作；
8. 出题资格从工单管理中拆出，成为可扩展的附加权限。

旧直接编辑组件、直接新建页面、旧题库总页面以及审批视觉说明均已退出当前架构。

## 6. 前端与后台演进

前端先后完成公共导航、课程空间、考试三步发布、团队空间、比赛子路由和题库筛选重构。算法标签最终统一为可搜索、多选的弹出式选择器。

后台第三版主题保留校方品牌，但首页从设计稿驱动的卡片入口调整为真实数据驱动的教学概览。用户列表和附加权限拆成子路由；工单管理只处理题目数据工单。阶段性设计参考图和自动化对比截图已经完成验收使命，不再随源码长期保存。

此后继续完成了两项工程治理：API 以 `apps/api/openapi/openapi.json` 为单一契约源，自动生成 TypeScript Client，并在构建阶段检查 Gin 路由和生成文件是否同步；前端建立全局语义视觉 Token，后台页头与区块标题改为公共组件，删除重复的细小说明文案。提交编辑器不再展示“代码仅计入当前范围”和“草稿自动保存”等提示，但草稿保存能力本身保留。

## 7. API 契约与视觉治理

- OpenAPI 覆盖当前 `/api` 与 `/api/v1` 的全部注册操作，并通过 `GET /openapi.json` 对外提供同一份内嵌文档；
- TypeScript Client、Schema 类型和 operationId 方法由 OpenAPI 自动生成；
- Web 生产构建会检查契约、Gin 路由和生成文件三者一致；
- Axios 配置与认证抽到独立 HTTP 层，现有页面通过生成模块的兼容出口渐进迁移；
- 全局 Token 分为画布、表面、文本、边框、主色、状态、圆角、阴影和后台语义别名；
- 后台教学概览、工单管理与权限管理复用公共页头，教学概览卡片复用公共区块标题；
- 后台删除无数据含义的副标题、卡片说明和权限说明列，保留状态、范围、影响和审核材料等必要信息。
