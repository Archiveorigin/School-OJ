# 开发沿革

本文把过去分散的执行计划、页面研究、组件规格和视觉验收记录合并为可维护的历史说明。当前功能以 [功能说明](features.md) 和代码为准。

## 1. 基础平台阶段

项目最初建立 API、Worker、Web 三应用结构，完成用户、课程、班级、题库、作业、考试和基础排行榜，并使用 PostgreSQL、Redis、MinIO 和 Docker 组成可独立部署的学校 OJ。

随后补充个人资料、注册找回、邮件验证、审计日志和 JPlag 工作流，使平台从单纯判题服务扩展为完整教学系统。

## 2. 判题可靠性与安全阶段

主要演进包括：

- Redis Streams 消费组和 pending 任务回收；
- 每提交可续期租约和幂等状态判断；
- 提交与 Transactional Outbox 同事务写入；
- 状态、测试点和进度的事务性最终写入；
- SSE 实时通知与低频对账；
- cgroup CPU/峰值内存计量和 OOM 识别；
- Docker 禁网、只读根、非 root、capability、seccomp、pids 和输出限制；
- 精确、令牌和浮点误差三种内置比较器。

这些能力最终形成当前统一判题链，普通练习、作业、考试、团队比赛和题单不再维护不同的判题实现。

## 3. 教学与团队阶段

课程和班级从简单列表扩展为课程空间，支持多班级加入、课程邀请码、成员管理、作业与考试上下文。

团队功能经历了团队入口、成员权限、题单、比赛生命周期、场内字母题号、上下文提交和排行榜的逐步完善。比赛从页面内 Hash 标签改为真实子路由，并明确与校内考试的业务边界。

## 4. 排行榜演进

早期系统使用 `score` 和 `penalty` 两种内部值，并分别维护考试、比赛及独立排行榜页面。之后抽取了共享排行榜组件、排序适配器、奖项比例、固定列和移动端横向滚动。

当前业务统一为 OI、IOI、ACM：

- 旧 `score` 数据迁移为 IOI；
- 旧 `penalty` 数据迁移为 ACM；
- OI 增加最后提交计分和赛中严格隐藏；
- IOI/ACM 增加封榜；
- 团队比赛放弃独立视觉，完全复用考试排行榜；
- 无路由的独立排行榜页面和旧版视觉规格已删除。

组件内部仍可能使用 `score`、`penalty` 作为两类表格适配名称，它们是展示层兼容术语，不是对外赛制选项。

## 5. 题目管理演进

题目最初支持页面直接创建、编辑、删除、测试点替换和审批。随着考试和比赛场景增加，直接覆盖题目会改变已开始场次的内容，因此后来完成以下重构：

1. 新增不可变 `problem_versions`；
2. 考试题目、比赛题目和提交绑定版本；
3. 旧题包生成版本 1 并回填历史关系；
4. 所有写操作收口为题目工单；
5. 替换只同步未开始场次，历史场次保持原版本；
6. 删除改为归档，保留历史引用；
7. 工单参考附件改为必填，替换和归档明确采用覆盖操作；
8. 出题资格从工单管理中拆出，成为可扩展的附加权限。

旧直接编辑组件、直接新建页面、旧题库总页面以及审批视觉说明均已退出当前架构。

## 6. 前端与后台演进

前端先后完成公共导航、课程空间、考试三步发布、团队空间、比赛子路由和题库筛选重构。算法标签最终统一为可搜索、多选的弹出式选择器。

后台第三版主题保留校方品牌，但首页从设计稿驱动的卡片入口调整为真实数据驱动的教学概览。用户列表和附加权限拆成子路由；工单管理只处理题目数据工单。阶段性设计参考图和自动化对比截图已经完成验收使命，不再随源码长期保存。

此后继续完成了两项工程治理：API 以 `apps/api/openapi/openapi.json` 为单一契约源，自动生成 TypeScript Client，并在构建阶段检查 Gin 路由和生成文件是否同步；前端建立全局语义视觉 Token，后台页头与区块标题改为公共组件，删除重复的细小说明文案。提交编辑器不再展示“代码仅计入当前范围”和“草稿自动保存”等提示，但草稿保存能力本身保留。

## 7. API 契约与视觉治理

- OpenAPI 覆盖当前 `/api` 与 `/api/v1` 的全部注册操作，并通过 `GET /openapi.json` 对外提供同一份内嵌文档；
- TypeScript Client、Schema 类型和 operationId 方法由 OpenAPI 自动生成；
- Web 生产构建会检查契约、Gin 路由和生成文件三者一致；
- Axios 配置与认证抽到独立 HTTP 层，现有页面通过生成模块的兼容出口渐进迁移；
- 全局 Token 分为画布、表面、文本、边框、主色、状态、圆角、阴影和后台语义别名；
- 后台教学概览、工单管理与权限管理复用公共页头，教学概览卡片复用公共区块标题；
- 后台删除无数据含义的副标题、卡片说明和权限说明列，保留状态、范围、影响和审核材料等必要信息。

## 9. 已替换或删除的历史方案

- `/api/v2` 契约优先重构曾作为阶段计划提出，但当前实际稳定入口仍为 `/api` 与 `/api/v1`；文档不把未实现计划描述成现有能力。
- 早期 Score/Penalty 两套对外赛制已由 OI/IOI/ACM 取代。
- 团队比赛独立排行榜 UI 已由考试共享排行榜取代。
- 题目直接编辑、直接创建和测试点直接替换已由工单取代。
- 旧“出题管理”混合了资格与审批，当前已拆分为权限管理和题目工单管理。
- 页面像素规格、临时克隆工程、视觉参考图片和本机绝对路径已从长期文档中移除。

## 11. 治理方向的本轮落地（2026-09-07）

基于 `99c78d5` 继续开发。以下描述为 2026-09-07 的本地验收记录；后续发布状态见第 12 节。

| 治理方向 | 本轮实现 | 明确保留的边界 |
| --- | --- | --- |
| Handler 分层 | 团队准入与职级用例拆为领域策略、应用服务和 GORM 仓储；事务和并发规则集中维护 | 其余大型 Handler 按模块继续迁移，并未全量重写 |
| 可执行架构约束 | 权限矩阵、审批重放、依赖方向、API/Worker 版本字段及两套前缀等价测试 | 持续为新业务补充约束，不用目录搬迁代替授权测试 |
| 故障恢复 | 真实 PostgreSQL/Redis 验证 Outbox 补发、Worker 租约/pending 接管、终态落库失败不 ACK、迁移回滚和修正重试 | 故障在隔离测试客户端注入；Docker 沙箱另行验收 |
| 契约与视觉 | 业务 Axios 调用改为生成 operationId；补全公开代码和团队提交字段，保留 multipart/Blob/多段资源路径；团队与提交详情使用语义颜色 | 历史复杂响应仍有显式泛型适配；其他模块 Token 渐进收敛 |
| `/api` 治理 | Web 默认 `/api/v1`，增加版本响应头和去敏用量观察，制定 30 天及完整考试周期的下线门槛 | 未证明外部旧客户端零调用，因此保留 `/api`，不宣称已下线 |

功能上，邀请制改为“输入邀请码 → 预览 → 确认”，不再先索取团队链接；申请制按申请链接提交后由团队管理员审核。职级明确为创建者、管理员、团员，基础账号身份不变。提交详情复制按钮位于代码区域右上角，普通练习、作业、考试、团队比赛、题单及人工阅卷共用详情内容。移除旧阅卷源码样式、无引用的私有出题入口和已无业务调用的准入包装函数。

实现中同时修复迁移 advisory lock 跨连接风险、Worker 终态落库失败仍 ACK 的任务丢失风险、团队提交详情权限及榜单初次加载赛制闪变。移动端人工阅卷经过截图复核后修正了栅格最小宽度与按钮换行。

本轮可运行的本地验证包括前端单测/生产构建、164 个 OpenAPI 操作及生成一致性、前后端架构约束、API/Worker 全量测试、真实隔离 PostgreSQL/Redis 集成及两套 Compose 配置。Playwright 验收记录见 [部署与测试](deployment.md#4-测试与构建)，截图为忽略提交的构建产物。Docker Desktop 本地启动故障仍存在，不能把上述通过结果表述为应用镜像或完整容器验收通过；提交、服务器构建和 GitHub 推送须等待维护者确认。
