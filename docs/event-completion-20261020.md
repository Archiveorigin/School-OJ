# 场次完结与独立组题工作区

本次替代上一版“时间结束即归档”的规则。考试和团队比赛使用相同流程；原班级、课程、团队、赛制及排名可见性继续生效。

| 状态 | 管理人员 | 参与者 | 前台比赛归档 |
| --- | --- | --- | --- |
| 草稿 / 已退回 | 在组题工作区修改并提交整场审核 | 不开放试卷 | 不展示 |
| 待审核 | 内容锁定，管理员批准或退回；组题者可撤回 | 不开放试卷 | 不展示 |
| 未开始 | 已批准；开赛前可撤回，修改后须重新审核 | 可查看说明，不提供题目和附件 | 不展示 |
| 进行中 | 固定题目版本、附件和时间 | 按原权限进入，查看题目、下载附件、提交；排名遵守 OI/封榜/考试设置 | 不展示 |
| 已截止 | 保留阅卷和成绩核查；管理员可确认完结 | 仅说明和本人提交，隐藏题目、附件与排名；不能答题 | 不展示 |
| 已完结 | 只读；调整人工评分前须由管理员填写原因撤销完结 | 原权限范围内查看题目、附件、本人提交和允许公开的排名；不能答题 | 展示 |
| 已删除 | 保留审计与历史数据 | 不再访问场次及附件 | 永不展示 |

截止不会自动完结。管理员确认完结前，系统检查赛前审核、截止时间、剩余排队/判题任务和人工评分。撤销完结只回到已截止，不会重新开放答题。完结、撤销完结、人工评分与重判通过场次行锁协调，审核操作还检查修订号并保存日志。参与者页面定期刷新状态，并在已知截止时间隐藏已加载的试卷；所有读取和提交仍由服务端鉴权。

过期草稿、退回、撤回、未审核、删除场次都不因时间经过而进入归档。开始时间已到的待审场次必须重新安排时间，不能补批准后归档。题库工单继续生成新版本，不会悄悄替换场次固定版本。

## 组题与文件

管理人员通过说明页的“组题”进入 `/event-papers/:kind/:eventId/edit`。左侧管理本场题目并按题号搜索已有题，右侧提供题面预览、本场附件、说明与时间、审核记录。

新题须填写标题、题目描述、输入格式、输出格式和 1–20 组样例；样例输入可为空，输出必填。说明可选，空白时不生成标题。图片可插入对应题面段落并即时预览。结构化源与规范 Markdown 一起保存在不可变题包中，再次编辑可还原字段。旧题保留原格式；原始 Markdown 工单修改使结构化源过期时，重新编辑使用审核后的原文。

测试点支持 `.in/.out` 配对或 ZIP，最多 400 个文件、总计 128 MiB。预览最多读取 64 KiB，因此 100 KiB 文件不会整份渲染；超过 1 MiB 的文件使用 1 MiB 分片、最多三个并发上传，显示进度。分片绑定作者与场次，一小时未使用自动清理，服务端检查数量、长度、配对、解压上限、修订号与权限。

修改旧题明确选择保留、按原名称合并或完整替换测试点。合并保留未上传的测试点及权重；历史版本保留。本场附件单独管理，连同固定版本试卷统一送审。编辑题目离开时提示未保存内容。

## 迁移与验证

`033_event_completion.sql` 增加完结时间、操作人和说明，使用增量且可重复运行的迁移。**所有存量已截止场次都需要管理员确认完结，不自动补写完结人。** 迁移不改变题目版本、提交或既有审核结论。

本地验证：后端全套 Go 测试（真实隔离 PostgreSQL/Redis）、前端 36 个文件共 138 项测试、API 契约与类型检查、生产构建。Playwright 验证桌面与 390px 手机的考试/比赛流程：新题及图片、结构化字段重载、100 KiB 预览、分片上传、按名称合并、按题号加入旧题、整场批准、私有附件、截止隔离、完结归档和删除排除。

发布流程使用本机 Git 管理代码，服务器隔离 Compose 构建并验证真实判题、生产数据副本的 PostgreSQL 16 迁移及重复执行；生产备份与隔离恢复成功后才切换应用镜像。清理限于本次验收容器、临时卷和无引用构建镜像，保留生产数据、备份和回滚镜像。
