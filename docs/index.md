## 每次开发的文档步骤

1. 在历史文档新增一条记录，保存用户原始提示词、后续答复、确认的边界。原文缺失时明确标为需求摘要，不补写成用户原话。
2. 阅读受影响模块的现行规则，记录需澄清的冲突；将最终规则直接更新到模块文档，不为每轮修改新建日期文件。
3. 完成实现、契约与迁移；测试覆盖关键行为、越权、并发和历史数据兼容性，界面变更覆盖桌面与手机、浅色与暗色。
4. 在同一历史条目按需求逐项填写验收结果。区分本地、隔离容器和正式环境，跳过或未执行的检查不能写为通过。
5. 发布遵循已授权的顺序，记录候选树、运行镜像、备份和提交身份；正式验证后补记发布结果。
6. 检查本地链接、入口与源码是否一致；截图、日志、备份、密钥留在受控产物目录，Git 只保留必要引用。

独立保留权限方案、题包规则和存储迁移方案等长期规范。历史方案被替换时写明替代关系，不把过时步骤继续放在当前操作文档中。
