# 考试与比赛整场审核、归档及附件

> 后续状态与组题流程以 [2026-10-20 完结机制](event-completion-20261020.md) 为准：截止后须管理员确认完结才归档，已完结场次的人工评分须先撤销完结。

考试和团队比赛统一按“草稿 → 待审核 → 已批准 / 已退回”管理。管理人员在说明页组题、创建本场专属题目、上传本场附件，再提交整场审核；系统管理员在“考试与比赛审核”中查看题面、下载审核题包后作出决定。

## 生命周期

| 场景 | 行为 |
| --- | --- |
| 草稿、已退回 | 可以修改题目、题序、分值、时间和附件，修改递增修订号 |
| 待审核 | 内容锁定；可以撤回或由管理员退回 |
| 已批准、未开始 | 可以撤回；撤回后不能进入，修改后必须重新送审 |
| 开始时间已到、仍待审核 | 不允许补批准后自动归档，需退回或撤回并重新安排时间 |
| 已批准、进行中 | 学生按原班级、课程或团队权限进入；题目及附件锁定 |
| 已批准、已结束 | 前台“比赛”归档提供本场题目、附件和原权限允许的排名，不接收新提交 |
| 已删除 | 不再进入、下载或归档；保留历史提交及审计所需的数据 |
| 草稿、退回、撤回后到期 | 不视为有效完结，不进入归档 |

所有完整试卷变更和审核通过场次行锁及修订号校验串行提交。审核记录保存当次题目版本、场次设置及附件元信息。题目包和提交继续使用不可变版本；公共题库工单修订不再自动切换任何已组题场次，采用新版本必须在可编辑状态明确操作。

考试批准时保存名单，随后实际进入的有权限考生加入名单。退出班级不移除已保存的历史名单。团队比赛继续在批准时冻结参赛名单。归档访问仍检查当前原有访问权限；OI 和未开放的考试排名不会因归档而公开。人工评阅仍可更新存储的成绩。

## 新题、测试点与附件

本场新题带有场次归属，不进入公共题库，也不能被其他考试、比赛或作业引用。题面图片按本场固定版本读取。

测试点修改提供三种明确方式：保留、按名称合并、完整替换。合并保留未上传的测试点、已有顺序及权重，只替换匹配名称的输入输出；新增测试点追加。场次上传使用原配对名称，避免旧导入器把单独上传的第 9 组重新编号为第 1 组。重名、歧义、缺少配对文件及越界 ZIP 会被拒绝。历史版本与对象保留。

附件统一属于场次，每场最多 20 个、共 96 MiB，单个最多 32 MiB。管理员及本场管理人员可提前查看；学生必须在获准开始并进入本场后下载，结束后沿用归档权限。下载通过鉴权接口，以附件方式传输，禁用缓存，不公开对象存储地址。删除场次或失去访问权限后不能新建下载。

## 升级

迁移 `032_event_review_and_attachments.sql` 将尚未开始的存量考试及已发布比赛送入待审核，管理员需要在开始前确认。已开始和已结束的存量场次保留可用状态；既有草稿比赛保持草稿。迁移保存考试名单，并取消未来考试旧有的“到结束时间自动公开题目”安排；同题独立作业的发布安排保留。新场次仅通过权限受控的归档保留题目。

旧的比赛发布接口改为提交审核并要求修订号，不能直接发布；旧的添加、移除题目接口也检查审核冻结状态。新前端使用统一组题接口。已移除失效的考试组题向导及其旧请求封装。
